# 开启 Pi 模式

当用户提到 Pi（“让 Pi 做…”“Pi 帮我…”）或输入 `/pi:start` 时，先按这份说明，再确认模式。**不要自动派单。**

**以用户的语言为主**：用户用中文就用中文，用户用英文就用英文；不要默认中文。

## 这是什么

`cc-pi-team` 是一个 Claude Code 插件，让 Claude 和本机的 Pi 一起干活：

- Claude 负责计划、拆任务、审核、提交；
- Pi 是一个独立的编码 agent 进程，负责实际写代码；
- 两边通过 Pi 的无头 RPC 通道通信，插件把 Pi 的会话绑定到当前 Claude 对话。

## 原理

- **Pi 不是 Claude 的子智能体**。它有自己的进程、会话、上下文和模型配置，跑在独立进程里；Claude 关掉也不会带走它。
- **通信靠 Pi 的 `--mode rpc`**：Pi 原生支持 stdin/stdout 上的 JSON 命令和事件；插件用它发任务书（`prompt`）、收正文和工具调用、中途 `steer`/`abort`，不模拟终端、不截屏。
- **任务书是唯一的输入**：Claude 把计划写进任务书，Pi 按任务书执行；Pi 的汇报、工具调用和结果会实时写进会话文件。
- **插件做绑定和展示**：把这个 Pi 会话绑定到当前 Claude 对话；右侧面板读同一份会话文件，所以 Claude 和用户看到的是同一份输出。
- **可以中途干预**：Pi 跑偏时发 `steer`，要停时发 `abort`；不用重启，也不用重新派单。
- **会话可恢复**：一轮跑完 Pi 进程退出，但绑定还在；下一轮用 `bind` 恢复同一条会话，上下文不丢。
- **多开靠多目录**：一个工作区同时只能跑一个 Pi（`.pi-*` 固定文件名会互相覆盖）；一个 Claude 可以绑多个 Pi，面板 `[1] [2]` 切换；要同时跑多个，就给每个 Pi 一个独立运行目录。

**插件提供**：团队/协同写代码、只读审查、会话绑定与恢复、实时输出面板、中途纠偏、叫停、退出和清理。

## 注意

**`/pi:start` 不能单独运行，也不会自己派单。** 它只负责开启 Pi 模式并读这份说明；真正派遣必须配合：

- 团队/协同：`/pi:team`
- 只读审查：`/pi:review`

## 启用示例

Claude 实际派单用的命令：

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/pi-dispatch.sh" "<工作区>" "new" "start"
```

最后提示用户：

- 团队模式：`/pi:team`
- 审查模式：`/pi:review`
